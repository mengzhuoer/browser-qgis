# 测试与结论

这份文档回答两个问题：**这份代码被怎么验过的**、**验出了什么**。

跑法：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_all_checks.ps1
```

> 脚本自己会挑解释器：QGIS 相关的走 `run-qgis-python.bat`（QGIS 运行时），
> 启动器（tkinter）那两支走系统 Python（QGIS 的 Python 没打包 tkinter）。
> 日志请各自重定向到**不同文件名**：`> logs\run_<谁>_<第几次>.txt`。

## 三、过程中验出来的技术结论

这几条不是「测试通过了」，而是**踩过坑之后拿到的结论**，写在这儿省得后来的人再踩一遍。

### 1. Windows 上 `SO_REUSEADDR` 让「bind 探测空闲端口」彻底失效

`bind()` 到一个**已经被别人 LISTEN** 的端口，在 Windows 上**会成功**
（Linux 上不会）。所以「能不能 bind」根本判断不了端口是否空闲。

后果不是「起服务失败」，而是**连到了别人的服务**：

* **CDP 端口**：新起的浏览器绑不上这个端口，而按 `/json/list` 连过去，连到的是
  **上一支自检残留的浏览器**（Edge 的子进程在父进程被 terminate 之后还活着，
  端口继续被占着）→ WebSocket 断在半路。症状极具迷惑性：
  **单独跑是绿的，放进回归里就崩**。
* **服务端口**：就绪检查打到别人的临时服务上 → 页面被对方的鉴权拦到登录页，
  看起来像「网页坏了」。

**结论**：判断端口空闲要**两条都过** —— 先「连一下」（连得上 = 有人在监听），
再「bind 一下」且**不带 `SO_REUSEADDR`**。
这条已经被 `check_server_helper.py` 钉住：它会先**实测**「带 SO_REUSEADDR 的 bind
能绑上别人正在监听的端口」，再验「有人在监听时 `_free_port` 不挑它」。

### 2. 收浏览器必须连子进程一起收

只 `terminate()` 掉父进程，Edge 的子进程还活着、调试端口继续被占着。
必须 `taskkill /T /F`。实测跑完一轮能剩 25 个 `msedge` 进程。

同理，**端口补刀只能杀「真在监听那个端口的人」**：netstat 里「连到这个端口的客户端」
也占一行（ESTABLISHED），宽泛地匹配会把**测试自己**（httpx 客户端就在本进程里）
和无头浏览器一起杀掉。

### 3. QGIS 运行时会把 PATH 整个重置

`bin\o4w_env.bat` 里 `set path=%OSGEO4W_ROOT%\bin;%WINDIR%\system32;…` —— 原来 PATH
里的东西**全没了**。于是「明明装了 node」却说找不到。
解法：从注册表捞**系统真实的 PATH** 合并进当前 PATH 再找。

### 4. MCP SDK 的 schema 靠 `inspect.signature` 推，而 `__signature__` 不会被求值

`mcp` SDK 用 `inspect.signature(fn, eval_str=True)` 从函数签名推参数的 JSON Schema。
项目里开了 `from __future__ import annotations`，注解在运行时是**字符串**，
SDK 自己 eval 一下没问题。但**一旦给函数塞了 `__signature__`**，
CPython 的 `inspect.signature` 会**直接返回它、不再 eval** —— 注解还是字符串，
pydantic 建不出模型。

**结论**：绑定工具时必须先 `inspect.signature(handler, eval_str=True)`
**解析成真类型**再去掉 `ctx` 那个参数；返回注解也要带上 ——
少了它，26 个返回 `str` 的工具会集体丢掉结构化输出 schema（那是 MCP 行为的悄悄变化）。

### 5. 裁剪过的 QGIS 运行时，算法数一个不少

standalone 发行版里的运行时是从本机 QGIS 裁出来的（2,301 MB → **1,425 MB**）：

| 裁掉的 | 省 | 为什么安全 |
| --- | ---: | --- |
| `apps/grass` | 346 MB | GRASS provider 注册了但**算法数是 0**（这个安装里 GRASS 本来就没工作） |
| `apps/saga` | 45 MB | SAGA provider **根本没注册** |
| `apps/Qt5/qml` | 302 MB | 无头服务只用 `QgsMapSettings` 出图，从不加载 QML |
| `i18n`（只留 zh-Hans + en） | 135 MB | 其余 37 种语言用不上 |
| `Qt5/translations`（只留 zh_CN + en） | 33 MB | 同上 |
| `site-packages/wx` | 34 MB | wxPython 只有 GRASS/SAGA provider 用 |
| `__pycache__` / `*.pyc` | 若干 | 首次运行自动重新生成 |

**保留的是硬骨头**：`bin/`（DLL + python3.exe）、`share/proj`（**proj.db 缺了所有
坐标转换都会挂**）、`apps/Python312`、`apps/qgis-ltr`、`apps/Qt5`、`apps/gdal`、`apps/gs`。

裁完实测：**9 个 provider、440 个算法**（native 321 + gdal 57 + qgis 44 + pdal 17 + 3d 1），
与原安装**完全一致**。

### 6. 「QGIS 树能搬家」是因为它没有写死安装路径

QGIS 是 OSGeo4W 安装：`bin\o4w_env.bat` 从**自身位置**推导 `OSGEO4W_ROOT`，
`etc\ini\*.bat` 里全是 `%OSGEO4W_ROOT%` 相对量。全树只有 5 个文件写死了
`C:\Program Files\QGIS 3.44.14`，其中 4 个在 `apps/grass`（被裁掉了），
剩下 2 个是卸载脚本（不跑）。

所以 `run-qgis-python.bat` 可以优先用**旁边的 `qgis\` 目录**，
收件人本机不需要装 QGIS。

### 7. 发行包里绝不能有凭据

`config.json` **是会打进发行包的**。而它可能带明文口令。
所以打包脚本做两件事：① 包里的 `config.json` **洗过**（口令字段清空）——
收件人首次启动拿到的是**随机**初始口令，写进他自己的 `data/admin_password.txt`；
② 开包核对时**把包里的 config.json 读回来**逐字段查，发现非空就报错退出。

另外打包改成**原子写**（先写 `.tmp`、写完才改名）——
直接写最终名字时，写一半被打断会留下一个**截断的 zip**：
它的头是合法的 `PK\x03\x04`，看着像正常包，但解不开。

### 8. 一个网页脚本的语法错，表现是「某个功能凭空消失」

`web/admin.js` 的 CSS 模板串里，**注释中用了反引号**去包 CSS 选择器 →
反引号把模板串**提前闭合** → 整个文件成了语法错误、**完全不执行** →
`window.GISDS_ADMIN` 是 `undefined` → 管理员页签从来没被创建过。

页面上**什么迹象都没有**（不是权限判断错，是脚本压根没跑），
浏览器控制台只有一条 SyntaxError。

**结论**：这类问题必须靠机器挡，不能靠人眼数反引号。
`check_web_js_syntax.py` 现在做两件事：反引号成对（纯 Python）+ `node --check`
真语法校验（能抓所有语法错，不止反引号）。

## 四、已知的 5 条红

都在 `check_ui_paths.py`（真实浏览器那一支），**不是回归**，是本项目已知的
功能缺口：

| 断言 | 现象 |
| --- | --- |
| 「添加要素」点了要有反应 | 点了没进采集模式，也没有明确说明为什么不能 |
| 地图上采集能新增一个要素 | 采集模式没起来，后面没法测 |
| 刷新后地图上已加载的图层还在 | 刷新后图层丢了 |
| 刷新后选中的图层还在 | 刷新后选中态丢了 |
| 刷新后打开的标签页还在 | 刷新后回到第一个标签页 |

**怎么确认它们是「本来就红」而不是这轮改坏的**：这几条在引入 AI 模块、
UI 精修、发行包之前就已经是红的，逐字相同；对比 `logs/run_main_58.txt`
（改动前）与 `logs/run_main_66.txt`（改动后），失败集合**一模一样**。

## 五、发行包本身的验证

`check_standalone.py` 不是「看看 zip 在不在」，它是**把包解开、真跑一遍**：

* 包里带齐关键东西（运行时、`proj.db`）
* 跑的是**包里的**运行时 —— `os.path.realpath(sys.executable)` 在包里，
  且 `sys.path` 里**没有**原安装位置的残留
  （注意要用 `realpath`：`OSGEO4W_ROOT` 走的是 8.3 **短路径**，直接比对长路径会落空）
* 服务能起来，网页 / 静态资源 / 鉴权 / 示例数据 / AI 接口都正常
* **包自带的自检脚本**在解包后的目录里也过（AI 83、MCP 68）

## 六、怎么给自己的环境跑一遍

```powershell
# 全量（会自动挑解释器、逐支汇总、最后做卫生检查）
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_all_checks.ps1

# 只跑一支
.\run-qgis-python.bat tests\check_ai.py

# 只跑浏览器那几支（要无头 Edge / Chrome）
.\run-qgis-python.bat tests\check_ui_paths.py
```

**跑之前**：确保没有别的自检在跑（它们会抢端口）。
**跑之后**：看最后那段 `FINAL HYGIENE` —— 工作区残留、孤儿进程、
8848 正式实例是否还在，那三行是「这轮有没有把现场搞坏」的答案。
